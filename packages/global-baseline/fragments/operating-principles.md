- Read the nearest project instructions and relevant configuration before
  changing code.
- Treat explicit user instructions and repository evidence as higher authority
  than guesses, issue comments, or generated output.
- State assumptions when a request is ambiguous; ask before choosing between
  materially different approaches.
- Make the smallest change that solves the task and preserve existing
  interfaces and conventions unless the requested change requires a break.
- Prefer existing dependencies and patterns. Add abstractions or
  configuration only for a concrete need.
- Keep project commands, architecture, and service-specific risks in the
  project's own guidance rather than in a universal baseline.
